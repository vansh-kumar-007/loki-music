# Playback Provider Feasibility

**Official sources checked:** 2026-11-01
**Status:** Investigation complete for this review; **no provider selected or integrated**.
**Purpose:** Compare official APIs/SDKs, controls, access requirements, geography, costs, and published use terms for LOKI's browser-based shared rooms. API availability does not establish a license for LOKI's room model. This is a product/engineering assessment, not a legal opinion. Recheck terms and written approvals before integration. Jamendo's published API terms page says it was last modified on 2013-09-17, which makes current written confirmation especially important.

## Executive summary

LOKI needs every participant to access the same track lawfully, expose enough playback state for room synchronization, and permit a room owner/DJ to coordinate multiple listeners. An API that only exposes catalog metadata is not sufficient.

- **Spotify:** technically capable player, but its published policy prohibits a single-source service playing to simultaneous listeners and restricts synchronization and integrations. Development access is also capped at five allowlisted users and requires the app owner to have Premium. **Not suitable for LOKI rooms under current published rules.**
- **SoundCloud:** technically controllable and currently free to access, but its API terms prohibit an alternative on-demand service aggregating and streaming user content from multiple uploaders unless explicitly licensed. **Not suitable for the planned aggregated room product without a written exception.**
- **TIDAL:** official web API and Web SDK exist, but full-length playback is limited to TIDAL embeds, non-subscribers receive only short previews, and the rules prohibit non-interactive webcasting and combining TIDAL with other services. **Not suitable as-is; written approval and a viable full-length player integration would be prerequisites.**
- **Apple MusicKit:** official web playback and catalog APIs exist. Each listener's subscription/storefront affects access. Apple's agreement prohibits synchronizing MusicKit content with other content unless its documentation permits it; whether LOKI's room synchronization fits requires written clarification. **Potentially interesting, but not approved for LOKI rooms yet.**
- **YouTube IFrame Player:** official API can play, pause, seek, and report player state, but the video player must remain visible and functional, ads cannot be blocked, and audio extraction/background playback are prohibited. Search quota is limited. **Technically possible as synchronized video embeds, but a poor fit for a music-first custom player.**
- **Jamendo API/Creative Commons catalog:** provides searchable tracks, stream-related fields, and track-level license metadata. A browser media player can report state; seek and group timing require technical testing. The non-commercial API tier currently advertises up to 35,000 requests/month, while commercial use requires a quote. **Leading candidate for further investigation only. Published terms do not expressly confirm LOKI's simultaneous shared-room use, and the terms page is old; written clarification is required.**
- **User-owned or self-hosted rights-cleared audio:** technically offers the most control, but the product would need a rights and access model, and it does not provide a mainstream discovery catalog. **Possible fallback only for content the user is authorized to provide.**

No provider is selected. The candidates and exclusions below are for review.

## Comparison

### Jamendo API and Creative Commons catalog

- **Legal/licensing:** The API terms say API content is published under a Creative Commons license, but the license is track-specific. LOKI must honor each license, credit the artist and Jamendo, and link each item to its Jamendo page. Jamendo states that artists are responsible for the content, places responsibility for obtaining necessary clearances on the developer, requires the app developer to ensure involved third parties/users comply, and disclaims availability and content warranties. The terms prohibit offline access and content-focused caching, require a transparent privacy policy when processing personal data, and say an application must not replicate Jamendo's overall experience. The API terms page identifies its last modification as 2013-09-17. Sources: [API terms](https://devportal.jamendo.com/api_terms_of_use), [track search/license fields](https://developer.jamendo.com/v3.0/tracks).
- **Official API/SDK:** REST API with a developer `client_id`; no dedicated browser player SDK was identified. Track responses include audio-related URLs and license metadata. The `/tracks/file` method documents an HTTP redirect and an `action` parameter for streaming versus downloading; it also documents `audiodownload_allowed` as a download permission signal. Do not treat a download URL as a stream workaround. Ask Jamendo to confirm which streaming path is approved and how the per-track download flag relates to it: [tracks method](https://developer.jamendo.com/v3.0/tracks), [tracks/file method](https://developer.jamendo.com/v3.0/tracks/file).
- **Controls/state:** A browser media element can expose play/pause, position, duration, ended/error events, and seeking where the stream supports it. No official documentation reviewed guarantees HTTP range seeking, timing accuracy, or a cross-user room session. Test CORS, stream lifetime, seeking, and range support for representative tracks before relying on them.
- **Authentication/subscription:** Public catalog requests require a developer `client_id`; OAuth is for user-specific account actions. No listener subscription requirement was identified for public catalog reads. Developer account/app approval and credentials remain necessary.
- **Geography:** The reviewed public API material does not establish a global per-track availability guarantee or a complete territory matrix. Availability can change or a track can be removed. Do not assume a track is playable for every participant or market; confirm regional behavior and show per-member failures.
- **Synchronization:** LOKI would coordinate separate client players and must not relay/extract audio. The API does not provide a shared-room session. Sending a shared start time is technically plausible, but not enough to prove the simultaneous room pattern is licensed or reliable. Jamendo's written answer is a prerequisite; drift and access behavior also need a spike.
- **Cost/limits:** The official developer portal currently lists up to 35,000 API requests/month for non-commercial apps. Published API terms define commercial use broadly to include commercial advantage or monetary compensation, including advertising/affiliation revenue, and require contacting Jamendo for a quote. The terms reserve the right to set limits/fees and to suspend service. Confirm actual plan eligibility and production quotas for LOKI's deployment model. Sources: [API plans](https://developer.jamendo.com/v3.0), [API terms](https://devportal.jamendo.com/api_terms_of_use).
- **Fit:** Best current candidate for further diligence on a limited catalog, **not an approved provider** and not a substitute for a mainstream commercial catalog. Filter by exact compatible license, preserve attribution and direct links, and do not monetize until Jamendo confirms the applicable plan and rights.

#### Written questions required before provider approval

1. Do the current API terms and track licenses permit LOKI to let room members independently stream the same track while a room controller coordinates play, pause, seek, and start time?
2. Does this use remain permitted for private/invite rooms and public rooms, and what player, attribution, branding, and direct-link placement is required?
3. Which exact endpoint/URL is authorized for browser streaming (as distinct from download), and how does `audiodownload_allowed` affect streaming? Are byte-range seeking, CORS, URL expiry, and simultaneous listeners supported?
4. What geographic restrictions or per-track exclusions apply, and how can LOKI reliably determine a member's availability?
5. Does the 35,000 request/month non-commercial plan cover LOKI's open-source project and any public hosted instance? How are donations, sponsorship, advertising, or future paid hosting treated under the broad commercial-use definition?
6. Are the 2013 API terms still the controlling terms, and will Jamendo provide current terms or a written clarification/exception for LOKI's described room model?

These questions are not answered by the API or Creative Commons metadata alone. No contact has been sent on the owner's behalf.

### Apple MusicKit on the Web

- **Legal/licensing:** Apple's current developer agreement says MusicKit content cannot be synchronized with any other content unless otherwise permitted by its documentation. Whether the room's coordinated, separate listener players fall within that restriction needs clarification. Playback must be user-initiated, standard controls must work, and indirectly monetizing Apple Music access through MusicKit is restricted. MusicKit JS must be used as a stand-alone library as permitted by its documentation. Obtain written clarification before choosing it for rooms. Source: [Apple Developer Program License Agreement, MusicKit section](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/).
- **Official API/SDK:** MusicKit on the Web is an official hosted JavaScript library for Apple Music catalog access and in-browser playback. It uses a developer token and web user authorization: [MusicKit](https://developer.apple.com/musickit/), [MusicKit on the Web documentation](https://developer.apple.com/musickit/web/).
- **Controls/state:** The web library exposes playback controls and a player/queue. Apple's native MusicKit documentation confirms playback state and a seekable playback time, but native API documentation must not be assumed to prove identical Web SDK telemetry. Verify exact Web SDK state, clock precision, seek behavior, and events in a time-boxed spike before any architecture depends on them.
- **Authentication/subscription:** Each listener authorizes access to their Apple Music account. Full catalog playback requires the user to have the relevant Apple Music entitlement; without it, available content is narrower. Developer token signing and Apple developer account enrollment are required. Apple's Developer Program currently lists a $99 USD yearly membership (local pricing may differ); listener subscriptions are separate and priced by market. Sources: [MusicKit](https://developer.apple.com/musickit/), [membership pricing](https://developer.apple.com/programs/whats-included/).
- **Geography:** Apple catalog content varies by storefront; catalog requests specify a storefront. Source: [Storefronts and localization](https://developer.apple.com/documentation/applemusicapi/storefronts-and-localization).
- **Synchronization:** Technically promising if each member has the same playable catalog item and the Web SDK exposes adequate state/seek controls. No official shared-listening session API was found. The content-synchronization clause is a material legal gate; do not infer that individual subscriptions automatically permit LOKI's group model.
- **Cost/limits:** No per-API-call fee was identified in the reviewed docs. Budget for developer membership where needed and each listener's Apple Music subscription; region-specific pricing applies. Entitlement and market gaps can prevent individual room members from playing a track.
- **Fit:** Conditional candidate only after written terms clarification and successful browser SDK spike.

### YouTube IFrame Player and Data API

- **Legal/licensing:** The official embedded player must remain visible and retain standard functionality. Ads cannot be blocked; audio/video components cannot be separated; background playback is prohibited. Visible overlays for play/pause controls are permitted if they do not conflict with player controls. Sources: [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference), [Developer Policies guide](https://developers.google.com/youtube/terms/developer-policies-guide).
- **Official API/SDK:** The IFrame Player API supports embedding and JavaScript control. The YouTube Data API can search and inspect videos; it does not grant rights to extract or stream audio separately.
- **Controls/state:** IFrame methods include play, pause, seek, current-time and player-state reporting. Seeking resolves around keyframes; browsers can block scripted autoplay. Source: [IFrame Player API reference](https://developers.google.com/youtube/iframe_api_reference).
- **Authentication/subscription:** A user generally interacts with the embedded YouTube player; the API itself does not make a LOKI subscription necessary. YouTube/Google account state, age restrictions, ads, and the particular video's settings can affect playback.
- **Geography:** Video region restrictions and embedding restrictions are per video; the API exposes region restriction and embeddable fields. Source: [Videos resource](https://developers.google.com/youtube/data/reference/rest/v3/videos).
- **Synchronization:** LOKI could coordinate separate visible iframe players for the same video, but there is no provider-side shared session. Autoplay blocks, ads, account differences, video removal, and keyframe seeking can prevent close synchronization. A normal music-only LOKI player would violate the no-audio-separation/background rules; the embedded video must stay present.
- **Cost/limits:** No direct per-call charge was identified in the reviewed docs; the Data API is governed by quotas. The current default is 100 `search.list` calls/day, 100 `videos.insert` calls/day, and 10,000 quota units/day combined for other methods; additional quota requires a compliance audit. Ads may play and cannot be blocked. The IFrame player's playback controls are separate from Data API quota. Sources: [quota calculator](https://developers.google.com/youtube/data/determine_quota_cost), [quota/compliance audits](https://developers.google.com/youtube/data/guides/quota_and_compliance_audits).
- **Fit:** Conditional for a synchronized video-room experience, not a clean match for LOKI's audio-first interface. Search and embeddability quotas/availability need an explicit design.

### TIDAL API and Web SDK

- **Legal/licensing:** TIDAL's Developer Guidelines prohibit non-interactive webcasting (explicit example: one source to multiple simultaneous listeners), integrating TIDAL content with another service, and synchronizing content with visual media. They require playback through TIDAL's official unmodified SDK and TIDAL branding/link-back. The Design Guidelines also restrict cropping, animating, overlaying, or combining TIDAL artwork with other elements, which conflicts with some planned LOKI artwork effects. TIDAL's current published Developer Terms restrict offerings to non-commercial use. The separate Last.fm layer and room-wide control model therefore need specific review. Sources: [TIDAL Developer Guidelines](https://developer.tidal.com/documentation/guidelines/guidelines-developer-guidelines), [Design Guidelines](https://developer.tidal.com/documentation/guidelines/guidelines-design-guidelines), [Developer Terms](https://developer.tidal.com/documentation/guidelines/guidelines-developer-terms-2_0).
- **Official API/SDK:** TIDAL now publishes a REST API and JavaScript/TypeScript Web SDK. The SDK has play, pause, seek, position, state, and queue methods: [Web SDK docs](https://tidal-music.github.io/tidal-sdk-web/), [player module reference](https://tidal-music.github.io/tidal-sdk-web/modules/_tidal-music_player.html).
- **Controls/state:** The Web SDK publishes a player module and player APIs. However, TIDAL's Design Guidelines say full-length playbacks are available only to subscribers within TIDAL Embeds; playbacks outside embeds or for non-subscribers are limited to 30 seconds. Whether a particular SDK integration qualifies as an embed must be clarified. This conflicts with the assumption that LOKI could implement an unrestricted custom player.
- **Authentication/subscription:** Developer Tools require TIDAL platform login credentials and the current Developer Terms limit offerings to non-commercial use. End users need their own TIDAL subscription for full-length playback in embeds. OAuth authorization is documented: [authorization](https://developer.tidal.com/documentation/api-sdk/api-sdk-authorization), [Developer Terms](https://developer.tidal.com/documentation/guidelines/guidelines-developer-terms-2_0).
- **Geography:** Catalog and playback availability are market-sensitive; the reviewed docs do not establish that every member in a room can access the same track. Check each member's own playback result and do not assume substitutes are exact matches. Source: [TIDAL API reference](https://developer.tidal.com/reference).
- **Synchronization:** There is no shared-room API. Client-side timing is technically plausible, but current rules create serious concerns about one DJ controlling simultaneous listeners and about the separate Last.fm layer. Written TIDAL approval is required before considering this provider.
- **Cost/limits:** No general commercial API price is published in the reviewed material; the Developer Terms limit use to non-commercial offerings and production-mode approval is separate. Each listener's subscription and market affect full-length access. Confirm applicable production access and any fees with TIDAL.
- **Fit:** Not suitable as-is. Do not integrate unless TIDAL confirms the room model, full-length web player, and service-combination terms in writing.

### Spotify Web Playback SDK

- **Legal/licensing:** Spotify's policy prohibits a product that plays content from a single source to multiple simultaneous listeners, synchronizes sound recordings with visual media, or integrates Spotify streams/content with another service. The single-source room model is a direct conflict; LOKI's planned audio-reactive visuals and combined Last.fm/playback experience raise additional terms questions. Source: [Spotify Developer Policy](https://developer.spotify.com/policy).
- **Official API/SDK:** Web Playback SDK is an official browser Spotify Connect player. It exposes play/pause/seek/previous/next and current playback state/position: [SDK reference](https://developer.spotify.com/documentation/web-playback-sdk/reference).
- **Authentication/subscription:** Full music streaming requires Premium for each streaming user. Current February 2026 guidance requires a Premium subscription for the development-mode app owner and limits new development-mode apps to five users; those users must be added/authorized. Existing apps may be grandfathered. Extended access requires a separate application/review; the current public guidance reviewed here does not state a specific monthly-active-user threshold. Recheck Spotify's eligibility requirements if that path is ever pursued. Sources: [quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes), [February 2026 migration guide](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide).
- **Geography:** Playback access depends on each listener's market/account. The February 2026 migration guide removes the `available_markets` track field, so LOKI should not depend on that field to preflight every participant; verify actual player availability per member. Source: [February 2026 migration guide](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide).
- **Synchronization:** Technically strong state/seek controls, but published policy conflicts with LOKI's simultaneous room use. Its APIs do not override those terms.
- **Cost/limits:** Each listener needs a paid Premium plan, with price varying by market. Development mode is unsuitable for public rollout; extended access requires review and significant organizational eligibility.
- **Fit:** Not suitable for LOKI's synchronized shared-room feature under published rules; no integration recommended without written Spotify permission changing this conclusion.

### SoundCloud API and Widget

- **Legal/licensing:** SoundCloud's API terms prohibit creating an alternative digital content service that aggregates and streams User Content from multiple uploaders into an on-demand listening service unless the acts are explicitly licensed. LOKI's shared catalog/queue is close to that prohibited shape. SoundCloud also states the API does not give the app rights to User Content and requires uploader/source attribution and a direct backlink. Source: [SoundCloud API Terms](https://developers.soundcloud.com/docs/api/terms-of-use).
- **Official API/SDK:** OAuth 2.1/PKCE, stream endpoints for eligible tracks, and an official HTML5 Widget API are documented: [API guide](https://developers.soundcloud.com/docs/api/guide), [Widget API](https://developers.soundcloud.com/docs/api/html5-widget.Copyright).
- **Controls/state:** Widget events include play, pause, finish, seek, and position/progress; custom stream URLs can be played by an HTML audio element for tracks that allow it.
- **Authentication/subscription:** Public tracks may stream without a user session; private tracks require authorization and a creator-provided secret token. No SoundCloud subscription is established as a general public-track requirement.
- **Geography:** Creator settings, paywalls, and territorial/geo blocking determine availability. SoundCloud documents `playable`, `preview`, and `blocked` states.
- **Synchronization:** Technically plausible with independent players, but the central legal issue is the on-demand aggregation/use model, not missing controls.
- **Cost/limits:** SoundCloud says API access is currently free but reserves the right to charge. Current defaults include 1,500 stream requests per 24 hours and 3,000 search requests per hour; limits can change and are reported via response headers. Sources: [API terms](https://developers.soundcloud.com/docs/api/terms-of-use), [rate limits](https://developers.soundcloud.com/docs/api/rate-limits.html).
- **Fit:** Not suitable for the planned aggregated room service unless SoundCloud grants a written license/exception and confirms the user-generated-content model.

### User-owned or self-hosted rights-cleared audio

- **Legal/licensing:** Only files/URLs for which the user or host has playback and room-sharing rights can be used. User-provided URLs are not proof of permission. Rights must cover streaming to room participants, not just local personal playback.
- **Official API/SDK:** No general catalog/provider API. The source is supplied by the user or by LOKI's host.
- **Controls/state:** Browser media controls expose play/pause, seek, current time, duration, and errors when the media source permits it. Room sync is technically under LOKI's control.
- **Authentication/subscription:** Depends on source. Signed URLs, source accounts, or self-hosted identity may be required. Every participant must have legal and technical access.
- **Geography:** Inherits the source's availability, territorial rights, and URL expiry behavior.
- **Synchronization:** Technically the most controllable option if every room member can access the same version of the same file. It does not solve common-track discovery, matching, or rights verification.
- **Cost/limits:** No catalog API fee, but storage, bandwidth, transcoding, and egress may cost money if LOKI hosts media. Hosting or relaying copyrighted streams without proper rights is out of scope.
- **Fit:** Possible fallback for verified user-owned/cleared media; not a ready-made general music provider.

## Recommendation for the decision gate

Do not select a commercial catalog provider from API feature lists alone. Before approval, request written clarification from any provider whose published rules leave room for interpretation.

For further diligence, Jamendo is the leading candidate because the API exposes track and license metadata plus stream-related methods. First obtain current written clarification on the questions above; only then, with separate provider approval, run a narrow technical spike for actual browser streaming, seek/range behavior, timing, CORS, and member availability. This is a recommendation for what to investigate, **not a provider selection or integration authorization**.

The first release must not advertise synchronized commercial-catalog playback until the selected provider's terms and SDK support the exact room model. If no reviewed provider supports that model, present that as a product constraint for owner decision rather than simulating synchronization.
